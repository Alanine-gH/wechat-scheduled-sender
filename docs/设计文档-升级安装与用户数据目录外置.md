# 设计文档 · 升级安装卡死与用户数据目录外置

> 版本：v2.0.3
> 日期：2026-11-11
> 涉及文件：`electron/main.js`、`electron/preload.js`、`backend/update.py`、
> `backend/server.py`、`frontend/index.html`、`tools/migrate-user-data.bat`、`README.md`

## 问题（用户报告）

> 下载的最新安装包会放在软件的安装目录里，但是安装程序运行时需要完整删除软件
> 安装目录，此时正在有进程占用问题，删不掉文件夹导致安装不了，直接卡死，
> 同时卸载或安装会覆盖用户文件夹，而我又不想把用户文件放到～下面。

## 前提核实（先查再动手）

| 前提 | 核实结果 |
|---|---|
| NSIS 到底删什么 | `node_modules/app-builder-lib/templates/nsis/uninstaller.nsh:169` 是 `RMDir /r $INSTDIR`，**整个安装目录**一锅端；不是「覆盖」而是删除 |
| 删除发生在哪个阶段 | 更新安装时 `installSection.nsh` 调 `uninstallOldVersion`，旧卸载器先跑，再释放新文件 |
| 进程占用的真正来源 | 不只是下载的安装包。运行中的 `WeChatSender.exe` 与 Python 边车 `resources\python\python.exe` **本身就在 `$INSTDIR` 内**。`atomicRMDir` 遇到被占用文件返回非 0 → `Abort "Can't rename..."`（模板 155–164 行） |
| 默认 `CHECK_APP_RUNNING` | `allowOnlyOneInstallerInstance.nsh:50` 起的宏只按 `APP_EXECUTABLE_FILENAME`（主 exe）查进程，**不查 `python.exe`** |
| `customUnInstall` 能否救数据 | 不能。模板 238–239 行，它在 `RMDir /r $INSTDIR` **之后**执行 |
| `customInit` 能否救数据 | 模板 72–74 行在 `.onInit`，但此时 `$INSTDIR` 未必是旧安装路径（用户可在向导里改目录），且 `customInit` 只在安装器里编译（第 56 行 `!ifdef BUILD_UNINSTALLER` 的 else 分支），覆盖不全 |
| 现有路径 bug | 后端下载到 `<根>/data/temp/update/`，`main.js` 的 `openPath` 白名单却是 `<根>/temp/update/` —— **两边对不上**，「打开安装包」按钮本来就会被白名单拒绝 |
| 数据根现状 | `main.js` 里 `DATA_ROOT = APP_DIR`（安装目录），`data/ logs/ shots/ cache/ tmp/ runtime/` 全在里面 |

**GitHub 同类问题**（按规矩先搜、评估关联度）：

| 来源 | 关联度 | 结论 |
|---|---|---|
| electron-builder [#6865](https://github.com/electron-userland/electron-builder/issues/6865) / [#8131](https://github.com/electron-userland/electron-builder/issues/8131) / [#9181](https://github.com/electron-userland/electron-builder/issues/9181) | 高 | 证实「app 运行时卸载旧文件失败」是上游已知故障，不是本项目代码问题；官方没有可靠开关 |
| [NSIS 官方文档](https://www.electron.build/docs/nsis/) `nsis.include` → `build/installer.nsh` | 高 | 提供 `customRemoveFiles` / `customCheckAppRunning` 钩子，但 `customRemoveFiles` 要自己重写整套 `atomicRMDir`（模板 31–132 行），回归面大；[issue #7376](https://github.com/electron-userland/electron-builder/issues/7376) 显示这条路容易踩坑 |
| [#2181](https://github.com/electron-userland/electron-builder/issues/2181)「files are deleted after update」 | 高 | 上游确认更新会删安装目录里的额外文件，长期行为，不会改 |

**决策：不写 `installer.nsh` 自定义脚本。** 理由：钩子时机不可靠、要重写复杂删除逻辑、
且违反「不擅自引入额外构建配置」。改为在 app 侧把数据搬出 `$INSTDIR`，从根上让
NSIS 删不到用户数据。

## 方案（用户拍板的三项决策）

| 决策点 | 选择 |
|---|---|
| 数据根位置 | 安装目录**同级** `WeChatSender-Data\`，且可通过界面自定义 |
| 老数据 | 首次启动自动**移动**过去（幂等，跨盘失败退化为复制并保留源） |
| 点安装时 | **弹确认框由用户决定**，确认后才退出程序并安装 |

### 改动清单

| 环节 | 改动前 | 改动后 |
|---|---|---|
| 数据根 | `APP_DIR`（安装目录内） | `APP_PARENT/WeChatSender-Data`；优先级 `WCS_DATA_ROOT` 环境变量 > 同级 `WeChatSender-Data.location.json` > 默认 |
| Python 侧 | 靠 `--dataroot` / 环境变量 | `process.env.WCS_DATA_ROOT = DATA_ROOT`，`userdata.configure` 自动跟随 |
| `app.setPath` | 指向 `<安装目录>/runtime` | 指向 `<数据根>/runtime`，其余同理 |
| 下载目录 | `<根>/data/temp/update`（安装目录内） | `<数据根>/updates/`（安装目录外） |
| `openPath` 白名单 | `<根>/temp/update`（与后端不一致） | `<数据根>/updates`，且改为 `showItemInFolder` 只展示不执行 |
| 安装动作 | `shell.openPath` 直接运行 | 新增 `wcs:install-update`：路径白名单 → 确认框 → `stopPython()`（Win 上补 `taskkill /T /F` 进程树）→ detached PowerShell 延迟 3 秒启动安装包 → `app.quit()` |
| 前端 | 「打开安装包」 | 「退出并安装」；新增「用户数据目录」卡片（显示 / 详情 / 自定义 / 恢复默认 / 打开目录） |
| `/api/app` | — | 增加 `data_root` / `updates_dir` 字段 |

### 为什么这三条各自必要

1. **数据外置** → NSIS `RMDir /r $INSTDIR` 只删程序文件，用户数据在同级目录，
   卸载/覆盖安装都碰不到。满足「不放 ~ 下」。
2. **安装包放 `<数据根>/updates`** → 安装包不会自己删自己，也不会占着 `$INSTDIR`。
3. **点安装时退出程序** → 释放 `WeChatSender.exe` 与 Python 边车的句柄，
   `atomicRMDir` 不再 Abort。这是解决「卡死」的关键，单靠 1、2 不够。

### 安全约束

- `wcs:install-update` / `wcs:open-path` 都校验路径必须在 `<数据根>/updates/` 下
  且以 `.exe` 结尾，渲染进程不能借此执行任意文件。
- `wcs:set-data-root` 拒绝把数据根指回安装目录（含子目录），拒绝不可写路径。
- 自定义配置写在**安装目录之外**的同级 `.location.json`，不会随升级被删。

## 老版本（v2.0.2 及更早）升级 —— 必须人工做一步

**这是无法回避的前提**：老版本程序里没有迁移代码，数据也在安装目录里。
新安装器会先执行 `RMDir /r $INSTDIR` 删掉整个安装目录，**新版本首次启动的
自动迁移来不及救**。

所以从 v2.0.2 升级这一次，先运行：

```bat
tools\migrate-user-data.bat "D:\soft\WeChatSender"
```

脚本把 `data/ logs/ shots/ cache/ tmp/ runtime/` 六个目录**移动**到
`<父目录>\WeChatSender-Data\`，不删除任何东西、可重复运行、目标已有数据时跳过。
之后再运行新安装包即可。v2.0.3 及以后升级不再需要。

## 已知限制（诚实说明）

1. **未做真机 NSIS 升级端到端验证**：需要实际安装、升级、卸载各跑一遍，
   会改动使用者机器上的软件。已做静态检查、前端 `node --check`、
   路径一致性单测，并打包验证 NSIS 能编译。
2. **如果用户手动双击下载的安装包而不走「退出并安装」**，程序仍在运行，
   仍可能撞上 exe 占用。界面与 README 都明确提示用按钮安装。
3. 自定义数据目录**只改引导文件、不搬现有数据**：切换后旧数据留在原目录，
   界面已明确提示「当前数据不会自动移动」。这是刻意选择，避免静默大批量搬文件。
4. 跨盘迁移时 `fs.renameSync` 会抛 `EXDEV`，退化为 `fs.cpSync` 复制并**保留源**，
   日志记录 `xxx(复制,源保留)`，不静默删用户文件。
5. 数据根默认名固定为 `WeChatSender-Data`；如果同一父目录下装了两份程序，
   它们会共用同一个数据根。需要隔离时用自定义目录区分。
